# 안 찍힐 때 확인할 것

증상이 대부분 "네트워크 문제"처럼 보여서 엉뚱한 곳을 파기 쉽다.
실제로 겪은 것들을 원인별로 적는다.

## 급지도 커팅도 되는데 백지만 나온다

**감열지가 뒤집혔다.** 열에 반응하는 면이 헤드(위)를 향해야 한다.
손톱으로 긁어 검은 줄이 나는 쪽이 발색면이다.

소프트웨어 문제와 구분하려면 새까만 래스터 블록을 보내 본다.
그래도 백지면 용지 방향이다.

## 한글이 깨진다

**내장 폰트에 한글이 없다.** 문자셋이 GB18030 / ASCII / BIG5 뿐이다.
Pillow 로 이미지를 그려 `GS v 0` 래스터 명령으로 보내야 한다
(`escpos_kr/raster.py`).

같은 네 줄이 텍스트로는 224바이트, 래스터로는 13.7KB. 60배 무겁다.

## Python 만 `No route to host` 가 난다

라우트도 ARP 도 멀쩡하고 `ping` 과 `nc` 는 되는데 Python 만 막히면
**macOS Sequoia 의 '로컬 네트워크' 권한**이다. 권한 없는 Homebrew Python 은
LAN 접속이 `OSError: [Errno 65]` 로 차단된다.

라우팅 문제로 오진하기 쉽다. `escpos_kr/transport.py` 의 `Network.send()` 에 `nc` 폴백을
넣어 우회해 두었다.

## USB 로 보냈는데 깨져 나온다

**macOS 가 raw 큐를 폐지했다.** `lpadmin -m raw` 는
"원본 대기열이 macOS에서 더 이상 지원되지 않습니다" 로 거부되고,
일반 PPD 를 쓰면 ESC/POS 바이트가 가공되어 깨진다.

CUPS **USB 백엔드를 직접 호출**하면 통과한다 (sudo 불필요):

```bash
/usr/libexec/cups/backend/usb          # 인자 없이 = 장치 URI 탐색 (여기서 나온
                                       # URI 를 그대로 DEVICE_URI 에 넣는다)
DEVICE_URI='usb://Printer/POS-80?serial=XXXXXXXXXXXX' \
  /usr/libexec/cups/backend/usb 1 "$USER" job 1 "" payload.bin
```

## 설정 페이지(192.168.4.1)가 빈 응답만 준다

**웹서버가 HTTP/0.9 로 답한다.** 상태줄도 헤더도 없이 본문만 보낸다.
그래서 `nc` 로 만든 생 요청도, 평범한 `curl` 도 아무것도 못 받는다
(`curl: (1) Received HTTP/0.9 when not allowed`).

`curl --http0.9` 를 써야 한다. 브라우저만 열리고 명령줄은 전부 안 되는 것처럼
보여서 오래 헤맸다.

## 설정 페이지가 아예 죽었다 (포트까지 닫힘)

**이 Wi-Fi 모듈은 동시 접속을 하나만 받는다.** 요청을 연달아 보내면
웹서버가 죽고 포트까지 닫힌다. 전원을 다시 넣어야 살아난다.
한 번에 하나씩, 간격을 두고 보낼 것.

## 맥북이 프린터 AP 에 갇혔다

AP 에 붙었다 돌아올 때 **SSID 이름에 의존해 복구하면 안 된다.**
위치 권한이 없으면 `networksetup -getairportnetwork` 가 SSID 대신
`"You are not associated with an AirPort network."` 라는 **문장**을 돌려준다.
그 문장을 SSID 로 넣어 복구를 시도하니 실패한다.

대신 AP 를 기억 목록에서 지우고 Wi-Fi 전원을 껐다 켜서, 키체인에 저장된
네트워크로 자동 재접속시킨다 (`docs/pos-8390/ap_fetch.sh` 의 `restore()`).

## 구분선이 접히거나 오른쪽 글자가 잘린다

`ESCPOS_WIDTH` 가 실제 인쇄 폭보다 큰 것이다. **헤드 폭과 인쇄 폭은 다르다** —
POS-8390 은 셀프테스트에 640 dot 이라고 찍지만 종이에 나오는 것은 576 까지라,
640 으로 그리면 우측 정렬한 글자와 이미지의 오른쪽 변이 날아간다.

확인법: 50자짜리 줄자를 찍어 본다.

    p.text("....|....1....|....2....|....3....|....4....|..48")

`48` 이 다음 줄로 넘어가면 그 프린터의 한 줄은 48자다. 58mm 라면
`ESCPOS_WIDTH=384`. 그래도 안 맞으면 `ESCPOS_COLUMNS` 로 직접 지정한다.

## 한글만 번진다 (영문은 멀쩡한데)

**온도 문제가 아니다.** 203dpi 는 1mm 에 8점이고, 28px 한글은 3.5mm 다.
그 안에 초성·중성·종성이 들어가니 획 하나가 1~2점인데, 감열 점은 원래
조금 번진다. 받침 있는 글자부터 뭉개진다. 영문 라벨이 또렷한 것은 그것이
프린터 내장 폰트라 이 해상도에 맞춰 설계되었기 때문이다.

두 가지 손잡이가 있고, **크기가 더 근본적이다.**

```python
Printer(font_size=32)          # 기본값. 28 이면 번진다
Printer(threshold=160)         # 획을 얇게. 기본 128, 높일수록 얇다
```

`threshold` 는 폰트가 글자 경계에 그리는 회색을 어디서 자를지 정한다.
올리면 획이 얇아지지만 너무 올리면(200 이상) 획이 끊어진다. 크기를 키울 수
없을 때만 쓴다. 환경변수 `ESCPOS_THRESHOLD` 로도 받는다 — MCP 로 쓸 때는
이쪽이다.

영수증 **위쪽은 선명한데 아래로 갈수록 번지면** 헤드에 열이 쌓인 것이라
원인이 다르다. 그때는 긴 출력을 나눠 보낸다.

## 농도(발열) 명령이 듣지 않는다

POS-8390 은 `ESC 7 n1 n2 n3`(발열 시간 조절)을 **지원하지 않는다.**
무시만 하는 것이 아니라 뒤따르는 숫자 세 개를 글자로 찍어 버린다.
영수증 중간에 `(` 나 `x`, `P` 같은 글자가 끼어 나왔다면 이것이다.
40 은 `(`, 120 은 `x`, 80 은 `P` 다.

확인법: 발열 시간을 40 과 120 으로 바꿔 같은 글귀를 찍어 본다.
진하기가 같으면 명령이 먹지 않는 것이다. 번짐은 위 항목으로 해결한다.

## 로고가 용지 폭을 다 잡아먹는다

`image()` 는 기본으로 용지 폭에 맞춘다. 낙관·로고는 작게 쓰는 것이 보통이니
폭을 지정한다. 래스터 명령은 늘 왼쪽 끝에서 시작하므로, 가운데나 오른쪽에
두려면 여백째 보내야 한다 — `align` 이 그 일을 한다.

```python
p.image("seal.png", width=160, align="right", dither=False)
```

80mm 용지에서 낙관은 120~200 dot 쯤이 보기 좋다. 선화는 `dither=False` 다.

## 로고가 새까만 사각형으로 나온다

배경이 투명한 PNG 였고 그 투명한 영역이 전부 찍힌 것이다. 지금은 흰색으로
합성해서 보내지만(`raster._flatten_alpha`), 직접 만든 이미지를 보낼 때는
`RGBA` 를 흰 배경에 올린 뒤 넘기는 편이 안전하다.

## "전송이 도중에 끊겼습니다" 가 나온다

일부가 이미 인쇄된 상태다. 라이브러리는 **자동으로 다시 보내지 않는다** —
다시 보내면 잘린 영수증 뒤에 온전한 영수증이 한 장 더 나오고, 커팅도 두 번
들어가기 때문이다. 용지를 보고 필요하면 직접 다시 보낸다.

연결 자체가 안 된 경우(한 바이트도 안 나간 경우)는 nc 로 자동 재시도한다.
이쪽은 중복 인쇄가 생길 수 없다.

## 엉뚱한 프린터로 출력된다

USB 장치가 여러 대일 때 영수증 프린터를 잘못 고른 것이다.

```python
from escpos_kr import find_usb_devices
find_usb_devices()        # 후보 전부
```

MCP 의 `list_printers` 도 후보가 둘 이상이면 함께 보여준다.
원하는 장치를 `Printer("usb://...")` 로 직접 지정하거나 `ESCPOS_TARGET` 에 넣는다.

판별할 때 `serial=` 부분은 떼고 본다. 시리얼은 임의 문자열이라
모델명 패턴(`RP1`, `TM-9` 등)에 우연히 걸려 엉뚱한 프린터가 뽑힌 적이 있다.

## 쓰면 안 되는 것

`route -host <IP> -interface <en>` 은 **쓰지 말 것.** 대상 IP 를 맥북 자신의
MAC 에 묶는 permanent ARP 항목을 만들어 통신을 조용히 막는다.
대역이 겹칠 때는 Wi-Fi 를 잠시 끄는 쪽이 낫다.
